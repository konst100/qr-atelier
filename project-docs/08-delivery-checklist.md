# QR Atelier — порядок поставки

Этот документ описывает последовательность работы над продуктом. Каждый этап начинается после проверки предыдущего.

## Выполнено

- [x] Локальный QR-редактор: URL, текст, Wi‑Fi, контакт.
- [x] Экспорт PNG и SVG.
- [x] Логотип пользователя в центре QR с высокой коррекцией ошибок.
- [x] Цветовые пресеты, HEX-палитра и проверка контраста.
- [x] Статическая и динамическая модель ссылки в редакторе.
- [x] 11 языков: RU, DE, EN, FR, ES, IT, PT, NL, PL, TR, ZH.
- [x] Локальная библиотека QR.
- [x] Фирменный знак QR Atelier в SVG.
- [x] 43 автоматических теста.
- [x] Публичный GitHub-репозиторий.
- [x] Закрытая Cloudflare demo-версия с Basic Auth.

## Следующие этапы

### 1. Онлайн-аккаунт — основа готова, runtime ещё подключается

Готово: экран регистрации/входа, клиент с `credentials: include`, provider-neutral API регистрации, входа, текущей сессии и выхода, PBKDF2-хэширование пароля и secure cookie. Проверено: 14 API-тестов проходят, пароль и токен не сохраняются в localStorage. Осталось подключить конкретный серверный runtime и SQL-провайдер.

В закрытом Cloudflare demo пока показывается статический интерфейс. Это ожидаемо: Assets не подключены к онлайн-базе, поэтому форма сообщает об отсутствии API, не создавая ложного аккаунта.

### 2. Онлайн-база и кабинет

Перенести сохранение QR из `localStorage` в SQL-базу. Проверка: QR сохраняется после перезагрузки и виден только владельцу.

### 3. Настоящая динамическая ссылка

Сохранять slug и текущий адрес на сервере. QR остаётся прежним, адрес меняется в кабинете. Проверка: старый QR ведёт на новый адрес после изменения.

### 4. Статистика

Собирать минимальные агрегаты сканирований по дням без лишних персональных данных. Проверка: счётчик и график соответствуют тестовым переходам.

### 5. Безопасность и запуск в Германии

Добавить Impressum, Datenschutzerklärung, удаление данных, резервирование, лимиты и проверку сетевых запросов. Юридический текст должен быть проверен по реальным данным оператора.

### 6. Производственная публикация

Выбрать платный сервер после сравнения цены, базы, резервных копий и региона обработки данных. Сначала закрытая бета, затем открытый запуск.

### 7. Монетизация

После проверки основного сервиса добавить тарифы, лимиты и оплату. До этого никаких платных функций не подключать.

## Что требует отдельного подтверждения

- смена тарифа или покупка услуг;
- подключение домена и платёжного провайдера;
- открытие демо без пароля;
- публикация Impressum/Datenschutz с персональными данными;
- удаление данных или репозитория.

Логины, пароли, токены и платёжные данные в репозиторий и переписку не записываются.
